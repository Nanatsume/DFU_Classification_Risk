# HANDOFF — อ่านก่อนแตะโค้ด

โปรเจกต์นี้คือ **capture_app** ระบบเก็บข้อมูลความเสี่ยงเท้าเบาหวาน (DFU) ของโรงพยาบาลพุทธชินราช
พิษณุโลก **ใช้กับผู้ป่วยจริงที่หน้างาน ไม่ใช่โปรเจกต์ทดลอง** — ข้อมูลที่เสียหายคือข้อมูลที่ต้อง
เรียกผู้ป่วยกลับมาตรวจใหม่

FastAPI + SQLite หลังบ้าน, React + Vite (multi-page) หน้าบ้าน, รันบนเครื่องเดียว ผูก `127.0.0.1`
ภาพรวมทั้งระบบอยู่ใน [`README.md`](README.md) และโน้ตแยกรายไฟล์/endpoint/ตาราง อยู่ใน
[`docs/notes/`](docs/notes/index.md)

## ติดตั้งครั้งแรก

ต้องใช้ **Python 3.12 เท่านั้น** — 3.11 ลง `numpy==2.5.1` ไม่ได้ และ `setup.ps1` จะปฏิเสธให้เอง

```powershell
cd capture_app
powershell -ExecutionPolicy Bypass -File setup.ps1
```

สคริปต์นี้สร้าง venv, ลง dependency จาก `requirements.lock.txt` (เวอร์ชันที่ทดสอบแล้วทุกตัว),
สร้างฐานข้อมูล, **รันเทสต์ทั้งชุด** เพื่อยืนยันว่าติดตั้งถูก แล้วโชว์รายชื่อกล้อง

จากนั้น:

```powershell
.venv\Scripts\python.exe tools\check_cameras.py      # ต้องเจอ Logi C615
powershell -ExecutionPolicy Bypass -File tools\setup_backup.ps1   # backup ขึ้น OneDrive
```

รันเซิร์ฟเวอร์:

```powershell
$env:APP_PASSWORD = "..."
$env:CAPTURE_SOURCE = "usb"            # ไม่ใส่ = โหมดจำลอง ได้ภาพตัวอย่าง ไม่ใช่ภาพผู้ป่วย
$env:DFU_DATA_DIR = "D:\dfu-data"      # ไดรฟ์ที่ backup ได้ อย่าไว้ในโฟลเดอร์โปรเจกต์
.venv\Scripts\python.exe -m uvicorn server:app --host 127.0.0.1 --port 8000
```

## ลำดับงานจริงหน้างาน — เพิ่งเปลี่ยน อย่าสลับกลับ

พยาบาลไม่มีเวลากรอกฟอร์ม 30 ช่องขณะผู้ป่วยนั่งอยู่ตรงหน้า ลำดับจึงเป็น:

```
กรอก HN → ระบบออก research id → ถ่ายภาพทันที
                                      ↓ ทีหลังตอนว่าง
        เปิด CRF ตรวจประจำปีของ รพ. ด้วย HN นั้น → กรอกฟอร์มของเราย้อนหลัง
```

research id ถูกออกตอน **"เริ่มเคส"** ไม่ใช่ตอนกรอกฟอร์ม — เพราะไฟล์ภาพถูกตั้งชื่อด้วย research id
ตั้งแต่เขียนครั้งแรก ทำให้ HN ไม่มีทางไปโผล่ในชื่อไฟล์หรือใน backup

เดิมเคยเป็น "ต้องมีฟอร์มก่อนถึงจะถ่ายได้" (409 gate) ซึ่งใช้ไม่ได้กับหน้างานจริง

## กับดักที่เคยกัดมาแล้ว — อย่าทำซ้ำ

### 1. อย่าทดสอบอะไรกับ `data/` ของจริง

**เกิดมาแล้ว 3 ครั้ง** ที่เทสต์เขียนทับข้อมูลจริง — รหัสผ่านทีมถูกแทนที่ด้วยรหัสเทสต์จนพยาบาล
ล็อกอินไม่ได้ และไฟล์ภาพของเคสจริงถูกเขียนทับด้วยผลจากภาพตัวอย่าง

ทุกครั้งสาเหตุเดียวกัน: มี **สำเนาของ path ข้อมูลมากกว่าหนึ่งที่** แล้ว patch ไม่ครบ

`server_paths.py` จึงอ่าน `db.DATA_DIR` **ทุกครั้งที่เรียก** ไม่ cache ไว้ตอน import
— อย่าเปลี่ยนกลับเป็นตัวแปร module-level ไม่ว่าจะดูสะอาดกว่าแค่ไหน

ตั้ง `DFU_DATA_DIR` ไปโฟลเดอร์ชั่วคราวเสมอเวลาทดลอง

### 2. กล้องเลือกจาก "ชื่อ" ไม่ใช่ index

อย่า hardcode `cv2.VideoCapture(1)` เด็ดขาด เครื่องที่ใช้งานมีกล้องเสมือน 4 ตัว
(OBS, Logi Capture, NVIDIA Broadcast, LSVCam) ที่ **เปิดได้และคืนเฟรมได้ปกติ** แต่เป็นภาพปลอม
และ index ขยับทุกครั้งที่เสียบ/ถอดอุปกรณ์ — เคยเห็นกับตาว่าถอดกล้องแล้ว `LSVCam` เลื่อนมาอยู่
index 1 แทนที่ podoscope พอดี

ถ้าหากล้องไม่เจอ ระบบจะ error พร้อมรายชื่อกล้องที่เห็น ไม่ fallback ไปตัวอื่นเงียบๆ

### 3. preprocessing ต้องรันเป็น child process

`tools/preprocess_one.py` เท่านั้น — เคยรันเป็น thread แล้ว **เซิร์ฟเวอร์ตายด้วย SIGSEGV**
ตอนที่มีการใช้กล้องพร้อมกัน (ผู้ใช้กดถ่ายซ้ำระหว่างรอ) พยายาม reproduce 3 ครั้งไม่สำเร็จ
จึงแยก process เพื่อตัดปัญหาทั้งชนิดโดยไม่ต้องรู้ว่าไลบรารีไหนผิด — **อย่าย้ายกลับเป็น thread**

### 4. Windows ภาษาไทยใช้ codepage cp874

`preprocessing.py` (export มาจาก notebook) มี `print` ที่มี `✓ ÷ ├ 📂` อยู่ 15 จุด ซึ่ง cp874
encode ไม่ได้ ตัวที่บรรทัด 33 รันตอน import ทำให้ **แอปบูตไม่ขึ้นเลย** และอีก 3 จุดอยู่ใน
`preprocess_foot_image()` ที่ถูกเรียกทุกครั้งที่ถ่ายภาพ

`stdio_utf8.force_utf8_stdio()` กันไว้แล้ว ต้องถูกเรียก **ก่อน** `import preprocessing` เสมอ
— อย่าลบ อย่าย้าย

เทสต์ทั้งชุดเคยเขียวอยู่ทั้งที่แอปบูตไม่ขึ้น เพราะ pytest ครอบ stdout ด้วย buffer UTF-8
`tests/test_console_encoding.py` จึงยิง subprocess จริงที่มี stdout เป็น cp874 จริง

### 5. ห้ามเปลี่ยน `PODO_ICM_MAX_ITER` เอง

ค่าเริ่มต้น **30** คือค่าที่เขียนไว้ใน proposal ที่ผ่าน IRB แล้ว

วัดแล้วพบว่ารอบที่ 8 ให้ mask ตรงกับรอบ 30 ที่ IoU 0.9999 และ ICM **ไม่มีวัน converge** เพราะ
สัดส่วนพิกเซลที่เปลี่ยนไปนิ่งที่ ~0.176% ขณะที่เกณฑ์ตั้งไว้ 0.1% — ลดเหลือ 8 รอบจะเร็วขึ้น ~70%

**แต่นั่นคือการเปลี่ยนวิธีการวิจัย ไม่ใช่การจูนพารามิเตอร์** ต้องให้เจ้าของโปรเจกต์คุยกับ
อาจารย์ที่ปรึกษาก่อน ตัวเลขที่วัดได้อยู่ในคอมเมนต์ข้างตัวแปรใน `preprocessing.py` แล้ว

### 6. HN คือข้อมูลระบุตัวผู้ป่วยชิ้นเดียวในระบบ

อยู่ที่ `cases.hn` คอลัมน์เดียวโดยเจตนา **ห้ามให้หลุด** ไปที่ชื่อไฟล์ / `meta/*.json` /
`fields_json` / CSV export ทั้งสองแบบ / cloud backup (`tools/backup.py` ล้างทิ้ง + VACUUM
ก่อนอัปโหลด)

`DELETE /api/hn` คือปุ่มล้าง HN ทั้งหมดตอนปิดโครงการ — **ย้อนกลับไม่ได้** และหลังจากนั้น
จะตรวจสอบค่าที่คัดลอกมากับต้นฉบับของโรงพยาบาลไม่ได้อีก

### 7. ไม่เก็บชื่อเจ้าหน้าที่ทุกชนิด

ฝั่งโรงพยาบาลขอมา — ทั้งพยาบาลผู้ตรวจและผู้ถ่ายภาพถูกถอดออกหมด ทั้ง schema, API และ UI
ผลคือระบบ **ไม่มีบันทึกว่าใครตรวจเคสไหน** ถ้าจะเพิ่ม audit trail กลับเข้ามาต้องถามเจ้าของ
โปรเจกต์ก่อน (ดูคำอธิบายใน `auth.py`)

## ข้อตกลงกับเจ้าของโปรเจกต์

- **commit ได้เอง** หลังงานใหญ่ที่ผ่านเทสต์แล้ว
- **ห้าม push / merge / เปิด PR เอง** โดยไม่ถามก่อน
- งานที่ **ลบข้อมูล** หรือ **เปิดสู่อินเทอร์เน็ต** (tunnel, `--host 0.0.0.0`) ต้องถามก่อนทุกครั้ง
- ถ้าไม่มี backup ขึ้นคลาวด์อยู่ ให้ทักเตือน — ข้อมูลอยู่บนเครื่องเดียวคือความเสี่ยงที่ไม่จำเป็น
